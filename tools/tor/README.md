# tor/ — self-contained Tor SOCKS5 fetcher for `.onion` sites

Pull data through the dark web without `sudo`. This folder ships a private
Tor daemon (SOCKS5 on `127.0.0.1:9151`, control on `9051`) plus a Python
fetcher that rotates identity per request.

Built and verified end-to-end: `fetch.py --json` returned HTTP 200 from the
live DuckDuckGo onion site (225 KB, correct title) in ~4 s with a fresh circuit.

## Files

| File           | Purpose |
|----------------|---------|
| `fetch.py`     | curl-backed fetcher — `--json` / `--text` / `--retry` / `--timeout` / `--out` |
| `torctl.sh`    | `start` / `stop` / `status` / `log` / `newidentity` wrapper |
| `newnym.py`    | identity rotation (`SIGNAL NEWNYM`) |
| `torrc`        | daemon config (SOCKS :9151, control :9051 cookie auth, `run/` data dir) |
| `setup.sh`     | downloads Tor + libevent from Ubuntu `.deb`s, extracts, starts the daemon |

`bin/`, `lib/`, `run/`, `onion-data/` are generated by `setup.sh` and gitignored.

## Setup (one time, no sudo)

```bash
cd tools/tor
./setup.sh          # downloads tor + libevent, extracts to bin/ lib/, starts daemon
```

Requirements: `curl`, `python3`, `dpkg-deb` (all in Ubuntu's base).

## Usage

```bash
# save a page to ./onion-data/<slug>.html
python3 fetch.py https://some-site.onion/path

# JSON: {url, status, time, title, bytes, ...}
python3 fetch.py --json https://duckduckgogg42xjoc72x3sjasowoarfbgcmvfimaftt6twagswzczad.onion/

# visible text only
python3 fetch.py --text https://some-site.onion/

# more retries, custom timeout, custom output dir
python3 fetch.py --retry 4 --timeout 90 --out /tmp/pulls https://some-site.onion/
```

Every request uses a **fresh Tor circuit** (`SIGNAL NEWNYM` + wait-for-established),
so repeated pulls look like different users.

## Managing the daemon

```bash
./torctl.sh status         # running (pid N) / stopped
./torctl.sh log            # last 20 log lines
./torctl.sh newidentity    # rotate identity now
./torctl.sh stop           # shut down
./torctl.sh start          # (re)start
```

## Gotchas (learned the hard way)

- **Fingerprint filtering:** some onion services (e.g. DuckDuckGo) reject Python's
  `ssl` ClientHello. `fetch.py` therefore delegates HTTP/TLS to **`curl`** via
  `--socks5-hostname`, which their servers accept. Don't "fix" it back to raw sockets.
- **Identity rotation:** `NEWNYM` as a command returns `510 Unrecognized command`;
  the reliable primitive is **`SIGNAL NEWNYM`** after `AUTHENTICATE`.
- **Cookie auth** must be **hex-encoded** (`cookie.hex().upper()`), not raw bytes.
- **Circuit-wait key** is `status/circuit-established` (reply ends `NNN OK\r\n`),
  not `circuits-established`.
- **HTTPS is the reliable path** for services that 301 HTTP→HTTPS; `fetch.py` follows
  redirects with `curl -L`.

## Notes / limits

- `fetch.py` is **GET-only** (no POST/forms), handles gzip (via curl) but not
  brotli, and doesn't pin specific relays/exit nodes.
- Only stdlib + `curl` needed — no `pip` deps.
